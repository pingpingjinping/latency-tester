# Rev3 기준 장비 맞춤 보정 — 2026-10-30

## 목적과 선택

사용자가 다른 Rev와 ms 숫자대를 우선 맞추고 차이를 경험적 보정값으로 적용하는 방향을 요청했다. 실제 접점 시각이나 테스터 내부 지연을 독립 측정하는 작업과 구분한다. 기존 원본과 과거 실험 결과는 수정하지 않는다.

앞선 [FUN60 50회](rev3-fun60-2026-10-30.md)에서 요청 기준 변동은 OUT 완료 관측 구간과 강하게 함께 움직였다. 반면 IN 기준 분산은 작았다. 따라서 기본 추정 기준을 원본 IN 기준으로 두고 사용자 보정값을 더한다. 이 선택이 모든 환경에서 최적이라고 검증한 것은 아니다.

```text
원본 누름 Rdown = Kd − T2
원본 뗌   Rup   = Ku − T2 − H
보정 추정 누름 = Rdown + Cdown
보정 추정 뗌   = Rup + Cup

Cdown = 기준 장비 Keydown 평균 − Rev3 기준 보드 Rdown 평균
Cup   = 기준 장비 Keyup 평균   − Rev3 기준 보드 Rup 평균
```

누름·뗌 보정값은 각각 독립적이다. 계산된 보정값은 IN 기준의 바이어스를 맞추는 값이며 물리적 테스터 자체 지연 D와 같은 뜻이 아니다. 결과에 절댓값이나 0 하한을 적용하지 않는다.

## 사용자가 앞서 제공한 Rev1 기준값

사용자가 예전에 올린 값을 사용하라고 명시해 이전 대화에서 실제 Rev1 관측값을 복원했다. 출처는 **2026-10-17 사용자 메시지(UTC 12:56:07, 12:59:26)**다. 아래 수치는 사용자가 보고한 값이며 원본 Rev1 CSV는 현재 작업공간에 없다. 추정 중간점 값을 Rev1 실측으로 대체하지 않았다.

| FUN60 Ultra / Rev1 유지시간 | 회차 | Keydown 평균 | Keyup 평균 |
| --- | ---: | ---: | ---: |
| 20ms | 50 | 0.58ms | 0.46ms |
| 30ms | 50 | 0.59ms | 0.74ms |
| 50ms | 50 | 0.57ms | 0.74ms |

20ms Rev1 결과에는 Keydown 범위 0.40~0.90ms, Keyup 범위 −0.20~1.10ms도 보고됐다. 기준 장비 역시 모든 개별 회차의 비음수를 보장한 데이터는 아니다.

이번 Rev3 CSV도 유지시간 20ms이므로 **20ms 행만** 기본 보정에 사용한다. 30/50ms 값은 섞어 평균하지 않는다. 사용자 보고값·출처·선택한 조건과 계산은 [기준값 JSON](experiments/rev3-2026-10-30/rev1-reference-values.json)에 기록했다.

## GMK70의 과거 비교값으로 교차 확인

사용자는 2026-10-17 GMK70 유선에 대해 **Rev1 약 10ms / Rev3 2.55ms / PTG 약 10ms**라고 보고했다(UTC 12:20:50). 당시 Rev3 원본 평균은 Keydown 2.55ms / Keyup 2.32ms였고 OUT 기준은 18.64/18.41ms, OUT→IN 평균은 16.09ms였다(UTC 12:09:51).

기본 보정 +7.334/+8.014ms를 당시 원본에 적용하면 Keydown **9.884ms**, Keyup **10.334ms**다. 누름 비교에 쓰인 약 10ms 보고와 대략 같은 숫자대다. 단, GMK의 기준 장비 값은 별도 누름/뗌의 정밀 평균으로 복원된 것이 아니므로 Keyup 10.334ms를 검증된 일치라고 해석하지 않는다. 이 대략값을 FUN60의 정확한 평균과 섞어 보정값을 다시 평균하지 않았다.

새 2026-10-29 GMK 접점 비교의 `prearmed` 35회는 IN 평균이 −0.583/−0.780ms여서 같은 보정 적용 시 약 **6.751/7.234ms**다. 과거 Rev3 원본 2.55/2.32ms와 서로 다른 실행이며 입력 키·USB 포트·브라우저 등 조건이 완전히 같다는 기록은 없다. 따라서 이번 보정이 모든 GMK 실행을 10ms로 만든다고 주장하지 않는다. 원본과 대략값의 구분은 [기준값 JSON](experiments/rev3-2026-10-30/rev1-reference-values.json)에 보관했다.

## 기본 보정값과 재계산

[보관된 FUN60 Rev3 원본](experiments/rev3-2026-10-30/fun60-wired.csv) 50회 IN 기준 평균과 맞추면 다음과 같다.

```text
Cdown = 0.58 − (−6.754) = +7.334ms
Cup   = 0.46 − (−7.554) = +8.014ms
```

| 항목 | 보정 전 IN 평균 | 보정값 | 보정 후 평균 | 최소 | P95 | 최대 | 보정 후 음수 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Keydown | −6.754ms | +7.334ms | 0.580ms | −0.966ms | 1.034ms | 1.234ms | 1/50 |
| Keyup | −7.554ms | +8.014ms | 0.460ms | −1.086ms | 0.614ms | 1.214ms | 1/50 |

이는 원본 50행의 재계산이며 새 코드의 하드웨어 재측정 결과가 아니다. 고정된 값을 더하므로 표준편차는 IN 원본과 같은 0.280ms / 0.259ms다. 평균을 맞추는 목적이며 모든 회차의 음수 제거를 보장하지 않는다.

서로 다른 날짜의 실행을 맞춘 경험적 프로필이다. 같은 키보드라도 실제 측정 키·USB 포트·브라우저 등의 조건이 완전히 같았다는 기록은 없다. 보정에 쓴 데이터의 평균이 목표에 맞는 것은 계산 결과이므로 새 측정으로 재현성을 확인해야 한다. 다른 키보드에서도 공통 바이어스가 유지되는지는 별도 확인한다. 이 보정값을 실제 테스터 내부 지연 D와 동일시하지 않는다.

## 이후 다시 맞추는 방법

같은 키보드·키·연결 방식·유지시간·PC 조건에서 기준 장비 평균을 구한 뒤 Rev3로 같은 키보드를 측정한다. 접힌 보정 설정에 기준 장비의 평균과 이름을 넣으면 현재 원본 IN 평균과의 차이를 누름/뗌 각각 계산한다. 기본 프로필로 돌아가려면 **이전 Rev1 기준으로 복원**을 누른다.

기준 장비 자체의 오차도 결과에 반영된다. 이 기능은 사용자가 요청한 기준 장비와의 수치 일치를 위한 것으로 절대 접점 지연을 검증하는 기능은 아니다.

## UI와 데이터 보존

- 기본 결과·그래프·CSV 하나를 유지하고 보정 설정은 접힌 `Rev3 보정 · 다른 테스터에 맞춤`에 둔다.
- `보정값 적용`은 누름/뗌 값을 직접 변경한다. `이번 측정 평균을 기준값에 맞추기`는 현재 성공한 Rev3 원본 IN 평균으로 값을 구한다. 실패·예열·재전송·불완전 값은 맞춤에서 제외한다.
- 적용 시 현재 결과를 원본에서 재계산한다. 보정에 쓴 USB/입력 시각이나 IN 원본은 변경하지 않고 이전 보정값을 중복해서 더하지 않는다.
- 설정과 보정 근거는 브라우저 localStorage에 저장한다. 측정 중에는 적용/맞춤/입력을 잠그고 각 회차에는 당시 설정을 복사한다. 저장소를 사용할 수 없어도 현재 측정은 가능하다.
- CSV 앞 29컬럼 위치는 유지하되 주 결과의 의미는 `timing_basis=in_offset`으로 명시한다. 이전 요청 기준 파일의 `out_request`와 구분한다.
- 뒤에 요청 기준 원본 2개, 보정값 2개, 보정 출처/기준 이름, 기준 장비 평균 2개, 기준 보드 IN 평균 2개, 사용 회차 수를 추가한다. 첫 결과값은 화면과 일치하며 보정 재계산이 가능하다.

과거 실험 파일과 SHA-256은 그대로 유지한다. FUN60을 0ms라고 가정하지 않으며 과거 사용자 보고값과 이번 Rev3 원본의 차이를 명시한다.
